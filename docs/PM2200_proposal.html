Proposal for approval

Adding power metering to the IES-WI-C6A

BossFarm, our client, wants to see a site's electricity use on their dashboard. We can deliver that by teaching our IES-WI-C6A device to read a Schneider PM2200 power meter. This page explains the plan and what needs your approval to start.

Client BossFarm Prepared by Alessandro Frondini October 2026

Decisions needed from you

  • Approve the plan and scope described below: a new firmware and installer for the IES-WI-C6A that reads the PM2200 and sends the readings to the existing server and dashboard.
  • Approve getting a PM2200 for final testing, either borrowed from BossFarm or purchased. Everything else is built and tested without it.
  • Agree that we go back to BossFarm with three questions (meter model, meter settings, how they want it shown on the dashboard) listed further down.

Nothing in the existing products changes. The current sensors, firmware and installer stay exactly as they are.

Our device already has the RS485 hardware on board, so no hardware change is needed. The work is software: the device firmware, an installer, and adding the new data to the server and dashboard BossFarm already use.

What will be delivered

Power-meter firmware

A dedicated version of the device software that reads the PM2200 and sends its data. WiFi and server setup work the same way as on today's devices.

Dedicated flasher tool

A separate installer with its own name and colour, so the power-meter software cannot be confused with the existing sensor tool.

Meter simulator

A software stand-in for the PM2200, so everything can be built and tested before the physical meter is available.

Dashboard integration

The power data stored on the Raspberry Pi and prepared for the dashboard, alongside the existing sensor data.

Commissioning checklist

A short step-by-step guide for connecting a real meter and checking the readings against the meter's own display.

Readings reported to the dashboard

Voltage L1 L2 L3 Current L1 L2 L3 Power per line Total power Power factor Frequency Energy consumed in Wh

The Wh figure is read straight from the meter's own energy counter, so it stays correct even if the device restarts.

What we need to confirm with BossFarm

These do not block the first six steps. They need answers before the real-meter step.

  1. Dashboard display. Is the per-device card idea above what they want? The exact look can be decided once data is flowing.
  2. Meter model. Which PM2200 variant they will deploy: PM2210, PM2220 or PM2230. The PM2230 adds harmonic analysis if that is ever of interest.
  3. Meter settings. The communication settings configured on their meter (address, speed, parity), or permission for us to set them at installation.
  4. Test meter. Whether they can lend us one PM2200 for the final check in step 7, otherwise we purchase one.

Assumptions and risks

Meter data layout

Schneider publishes the meter's internal data addresses separately. They will be checked against the official documentation before a real meter is connected. Until then, values are verified against the simulator only.

Real-world check

Wiring, communication settings and reading accuracy can only be fully confirmed with the physical meter, in step 7.

First version scope

Voltage, current, power, power factor, frequency and Wh energy. Reactive power, harmonics or energy exported to the grid can be added later without changing what is delivered now.

Existing devices unaffected

The current sensor firmware and flasher stay as they are. The power-meter version is separate.
